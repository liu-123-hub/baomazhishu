# 板块配置手册

## 一、分类体系概述

本系统采用层级化分类框架，将所有行业板块归入 **7 大核心分类**，确保板块归属清晰无重叠。

### 1.1 分类架构

| 分类代码 | 分类名称 | 业务说明 | 包含板块数 |
|---------|---------|---------|-----------|
| finance | 大金融 | 银行、证券、保险等金融服务板块 | 3 |
| consumption | 大消费 | 白酒、食品、医药、家电、文旅等消费板块 | 7 |
| technology | 大科技 | 电子、计算机、通信、传媒、半导体等科技板块 | 6 |
| energy_chain | 能源产业链 | 传统能源（煤炭、原油）等能源产业链板块 | 2 |
| new_energy | 新能源赛道 | 新能源整体及核心组件（电池等）板块 | 2 |
| power_infra | 电力基建领域 | 电网设备、传统基建等基础设施板块 | 2 |
| cyclical | 周期资源 | 有色、化工、钢铁、地产等周期性板块 | 4 |
| others | 其他 | 海外指数、贵金属等其他板块 | 2 |

**总计：28 个板块**

## 四、技术接入指南

### 4.1 配置文件位置

新增或修改板块时，需同步更新以下 **10 个文件**：

| 层级 | 文件路径 | 配置项 | 说明 |
|-----|---------|-------|-----|
| 核心定义 | `analyzer/index_calculator.py` | `SECTOR_NAMES` | 指数计算核心板块名称映射 |
| 后端配置 | `backend/app/config.py` | `SECTOR_NAMES`, `SECTOR_CATEGORIES` | 后端板块配置与分类体系 |
| 前端常量 | `frontend/src/core/constants.js` | `SECTOR_NAMES`, `SECTOR_CATEGORIES`, `SECTOR_COLORS`, `CATEGORY_COLORS` | 前端展示配置 |
| 行情采集 | `collectors/market_data_collector.py` | `SECTOR_ETF_MAP` | ETF行情代码映射 |
| 股吧采集 | `collectors/guba_collector.py` | `SECTOR_ETF` | 东方财富股吧/ETF新闻配置 |
| 网易采集 | `collectors/netease_finance_collector.py` | `SECTOR_KEYWORDS` | 网易财经搜索关键词 |
| 同花顺采集 | `collectors/ths_finance_collector.py` | `SECTOR_KEYWORDS` | 同花顺搜索关键词 |
| 雪球采集 | `collectors/xueqiu_collector.py` | `SECTOR_KEYWORDS` | 雪球资讯搜索关键词 |
| 雪球社区 | `collectors/xueqiu_community_collector.py` | `SECTOR_KEYWORDS` | 雪球社区讨论关键词 |
| 小红书采集 | `collectors/xhs_collector.py` | `SEARCH_KEYWORDS` | 小红书搜索关键词 |
| 谷歌新闻 | `collectors/google_news_collector.py` | `SEARCH_KEYWORDS` | Google News RSS关键词 |

### 4.2 新增板块步骤

**Step 1：在核心定义中添加板块**

`analyzer/index_calculator.py` 的 `SECTOR_NAMES` 字典中添加：
```python
"sector_code": "板块名称",
```

**Step 2：在后端配置中添加分类**

`backend/app/config.py`：
1. 在 `SECTOR_NAMES` 中添加名称映射
2. 在 `SECTOR_CATEGORIES` 对应分类的 `children` 数组中添加板块代码

**Step 3：在前端常量中添加展示配置**

`frontend/src/core/constants.js`：
1. `SECTOR_NAMES` - 添加名称
2. `SECTOR_CATEGORIES` - 添加到对应分类
3. `SECTOR_COLORS` - 添加展示颜色（十六进制）

**Step 4：在采集器中添加关键词配置**

在每个采集器的关键词配置字典中，为新板块添加相关搜索词，建议每个板块配置 **5-12 个关键词**，覆盖：
- 板块/ETF通用名称
- 龙头股/代表性公司
- 细分赛道名称
- 产品/技术关键词

**Step 5：在行情采集器中添加ETF映射**

`collectors/market_data_collector.py` 的 `SECTOR_ETF_MAP` 中添加：
```python
"sector_code": {"code": "ETF代码", "name": "ETF名称", "ak_symbol": "sh/sz+代码"},
```

同时更新 `collectors/guba_collector.py` 的 `SECTOR_ETF`。

### 4.3 分类设计原则

1. **互斥性**：每个板块只能归属一个一级分类，禁止跨分类归属
2. **完整性**：所有板块必须归入某个分类，不允许存在未分类板块
3. **业务相关性**：分类按产业链/业务属性划分，而非简单按市值或热度
4. **可扩展性**：新增分类时需在前后端同步更新，并补充相应文档

### 4.4 冗余治理规则

定期执行冗余检查：
1. **重复板块排查**：检查不同文件中是否存在同一板块的不同代码
2. **无效板块清理**：移除已停用、长期无数据或业务合并的板块
3. **相似板块合并**：业务重合度超过80%的板块应考虑合并，细分需求通过子板块/关键词实现
4. **关联模块检查**：清理板块后需同步检查前端展示、数据统计、权限配置等关联模块

### 4.5 配置验证方法

修改配置后，通过以下方式验证：

1. **Python语法检查**：
```bash
cd backend
python -c "from app.config import settings; print(f'板块数: {len(settings.SECTOR_NAMES)}'); print(f'分类数: {len(settings.SECTOR_CATEGORIES)}')"
```

2. **一致性检查**：确保后端 `settings.SECTOR_NAMES` 与前端 `SECTOR_NAMES` 代码集合一致

3. **API启动测试**：启动后端服务，访问 `/api/v1/dashboard/overview` 确认无报错

4. **前端展示检查**：启动前端，确认板块分类树、颜色展示正常
